## Purpose

Defines "Integrations": how Minutes lets AI coding agents installed on the Mac read the saved meetings, through a
read-only skill installed in each agent's user skills folder and a dictionary file that Minutes keeps in the notes
folder.

## ADDED Requirements

### Requirement: Supported agents and detection
Settings › Integrations SHALL list Claude Code, Codex, GitHub Copilot, Gemini CLI and OpenCode. For each agent it
SHALL show whether the agent is detected on the Mac, whether the Minutes skill is installed, and the folder the
skill is installed in. An agent SHALL count as detected when its user configuration folder exists
(`~/.claude`, `~/.codex`, `~/.copilot`, `~/.gemini`, `~/.config/opencode`). The status SHALL refresh each time the
section is shown. Install SHALL be available only for detected agents.

#### Scenario: Two agents installed
- **WHEN** the Mac has Claude Code and Codex configured and none of the other agents
- **THEN** Integrations shows Claude Code and Codex as detected with an Install button, and the other three as not detected without one

### Requirement: Install the skill
Installing SHALL write a skill folder named "minutes" containing a SKILL.md in the agent's user skills folder:
`~/.claude/skills` (Claude Code), `~/.agents/skills` (Codex), `~/.copilot/skills` (GitHub Copilot),
`~/.gemini/skills` (Gemini CLI) and `~/.config/opencode/skills` (OpenCode). The SKILL.md SHALL follow the Agent
Skills format (front matter with name and description) and SHALL tell the agent the absolute path of the notes
folder, the path of the dictionary, the note format, how to find meetings (dictionary catalog first, then text
search in the notes), to cite the meeting title, date and file when answering, and that the notes MUST NOT be
created, modified, renamed or deleted. The skill SHALL carry a marker identifying it as generated by Minutes.

#### Scenario: Install for Claude Code
- **WHEN** the user clicks Install next to Claude Code
- **THEN** `~/.claude/skills/minutes/SKILL.md` exists, points to the current notes folder and the dictionary, and the row shows Installed

#### Scenario: Agent answers from the meetings
- **WHEN** after installing, the user asks Claude Code "what did we agree with Hemisphere about the delivery date?"
- **THEN** the agent can locate the relevant meetings through the dictionary and answer citing the meeting and its file, without changing any note

### Requirement: Never overwrite foreign skills
Minutes SHALL install, update or remove only a "minutes" skill folder that carries its marker. When a "minutes"
folder without the marker already exists, the row SHALL show a conflict, and Minutes SHALL NOT write or delete
anything there.

#### Scenario: Name already taken
- **WHEN** `~/.gemini/skills/minutes/` exists and was not created by Minutes
- **THEN** the Gemini CLI row shows that a different "minutes" skill exists and offers no Install or Remove action

### Requirement: Keep installed skills current
Minutes SHALL rewrite every installed Minutes skill when the notes folder changes and when the app launches with a
skill content different from the installed one (for example after an update of Minutes), so installed skills
always point to the current notes folder.

#### Scenario: Notes folder changed
- **WHEN** the user changes the notes folder in Settings with the skill installed for Codex and OpenCode
- **THEN** both installed skills point to the new folder without any further action

### Requirement: Remove the skill
Removing SHALL delete the agent's Minutes skill folder after confirmation and SHALL NOT touch the notes folder or
the agent's other skills.

#### Scenario: Remove from Copilot
- **WHEN** the user clicks Remove next to GitHub Copilot and confirms
- **THEN** `~/.copilot/skills/minutes/` no longer exists and the row shows the skill as not installed

### Requirement: Notes dictionary
Minutes SHALL keep a Markdown file `.minutes/dictionary.md` inside the notes folder describing, for agents: the
note format (front matter keys, including the calendar, attendees and meeting link keys, summary markers, transcript line form, speaker labels You, Speaker N and Others,
sidecar and audio locations), the client tags and the topic tags in use, each with its number of
meetings, the summary types, the date of the last update, and a catalog of every meeting, newest first, with date,
time, title, duration in minutes, tags and file name. Minutes SHALL update it, atomically, whenever a meeting is
saved, a summary or tags change, the summary types change, or notes are added, changed or
deleted on disk. The dictionary SHALL NOT appear in the Meetings list.

#### Scenario: New meeting saved
- **WHEN** a meeting tagged "client/hemisphere-brands" is saved
- **THEN** the dictionary catalog lists it first with its date, title, duration, tags and file name

#### Scenario: New client detected
- **WHEN** a meeting is tagged "client/acme" for the first time
- **THEN** the dictionary lists "client/acme" among the client tags with one meeting

#### Scenario: Note deleted in Finder
- **WHEN** the user deletes a note file in Finder
- **THEN** the meeting disappears from the dictionary catalog

### Requirement: Integrations privacy notice
The Integrations section SHALL state that an agent using the skill reads the meeting notes and may send their
content to that agent's AI provider, and that the skill only allows reading.

#### Scenario: Open Integrations
- **WHEN** the user opens Settings › Integrations
- **THEN** the privacy notice is shown above the agent list
